# 协议包头与编解码边界验收

日期：2026-10-02（Asia/Shanghai）

## 测试思路

本测试针对 `shared/protocol` 的 `PacketHeaderCodec`。线上的 4 字节大端长度表示后续 7 字节元数据与 payload；合法消息体长度为 7 字节至 4 MiB，因此最大 payload 为 4 MiB − 7 字节。

| 验收项 | 输入与断言 |
| --- | --- |
| 1 字节到上限边界 | 分别使用 1 字节、最大值减 1 字节、最大值的 payload，实际编码再解码，核对长度、请求 ID、全部 payload 字节和缓冲区消费；最大值加 1 字节必须编码失败且不改变原缓冲区。 |
| 10000 帧随机分片 | 固定种子 `0xA11CE` 生成 10000 个长度为 1～64 字节的二进制 payload，交替使用请求/响应类型并递增请求 ID；将连续线序按 1～31 字节的随机块输入，逐帧核对 ID、类型、长度、字节内容和最终剩余字节数，同时断言输入块数不少于 10000。块边界可落在包头或 payload 中，也可能覆盖相邻帧。 |
| 超长与负数位型 | 分别输入 `kMaxPacketSize + 1`、`0x80000000` 和 `0xFFFFFFFF` 的大端长度前缀。第一种超出 4 MiB；后两种分别是有符号 32 位最小值与 `-1` 的位型，按无符号长度解析后同样超限。仅收到 4 字节就应返回 `Invalid`，不得触发帧回调或消费输入。 |
| 半包 | 对一帧的每个非完整截断位置分别测试：返回 `NeedMore`，不交付帧并保留全部已到字节；追加余下字节后恰好交付一帧并清空缓冲区。 |

## 运行结果

- 协议与缓冲区聚焦测试：16/16 通过，包含新增的 4 项验收测试。
- 普通非性能测试：115/115 通过。
- ASan/UBSan 单元测试：112/112 通过；补充负数下界后，新增的 4 项测试再次在 ASan/UBSan 下通过。
- ASan/UBSan 环境下现有 TCP 集成测试：4/4 通过。
- `git diff --check`：通过。

## 验收范围

`NeedMore` 表示 codec 还需输入。若此时发生 EOF，连接适配层应把留下的半包视为截断并关闭；当前 `TcpServer` 尚未接入 codec，仍运行原始字节 echo。因此本报告验证了 codec 的判定结果，尚未验证真实网络连接收到非法包或 EOF 半包时的断开动作。协议 4 MiB 最大消息体也尚未与 gateway 当前 1 MiB 缓冲/输出上限统一。
